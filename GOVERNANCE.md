# Governance

curtilage is maintained by **Emil M** (GitHub: mohanenm), who reviews and merges pull requests, makes releases and decides what goes in.

**How decisions are made.** Proposals start as an issue or a pull request. Changes to the rules that generate polygons are decided on evidence: the public benchmark (before and after, per view) and aerial imagery, as [CONTRIBUTING.md](CONTRIBUTING.md) describes. Changes to the public API follow the [versioning policy](README.md#versioning). The maintainer has the final say and explains the reason for any decision that isn't obvious from the discussion.

**Principles that guide decisions:** free map data and no hosting; rule-based (no machine learning in the method); no real site data in the repository; untrusted input is capped and checked; every option and output documented.

**Conduct.** Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md). Security problems are reported privately, as [SECURITY.md](SECURITY.md) explains.

If more maintainers join, this file will say who they are and how they share decisions.
